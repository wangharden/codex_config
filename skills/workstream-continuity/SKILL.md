# Workstream Continuity

唯一入口为 `E:\CodexWorkstreams`。不叠加旧 Wiki 的加载、收尾和编译技能；用户明确维护该 Wiki 时才采用其工作流。具体字段、写入载荷与命令见 `references/state-contract.md`，只在需要相应操作时读相关段。

## 接续与查旧结果

```powershell
python E:\CodexWorkstreams\skills\workstream-continuity\scripts\workstream.py resolve "<request>" --cwd "<cwd>"
```

1. 依据项目路径、别名和问题定位研究线；`E:\` 是有效跨项目工作目录。只有候选确有业务歧义时才询问，不要求用户手选旧 session 的最近几轮。
2. 用 `context` 读短当前状态及新鲜度提示；未指定问题时展开活跃清单首张（或标为main的）主卡，其余给查询指针。合并时把本轮焦点排在前面；按问题或ID可直接展开其他实验。检查修订、结论有效性、关键依赖及待合并增量；缺少依据应标尚未建立，不能宣称已核验新鲜。
3. 用 `experiments` 和 `rules` 先取最相关的1—3张卡与本次操作适用的纠正。召回结合问题、将改动的代码/数据及业务环节，不能只靠用户说出关键词。查旧结果可直达对应卡，不强制载入全条当前研究背景。
4. 从实验卡取得结论ID，再用 `conclusions <研究线> --id <结论ID>` 查询必要字段及当前可用性，也可按问题检索。只有方法细节、意图歧义或复现需要时才展开指定设计段、公开消息范围、Notebook单元或规范表字段；不整份读取大档案/Notebook。
5. 能说明当前问题、已做/未做、关键口径和限制、下一动作后停止背景读取；关键依据未知时继续补具体缺口，不能用字数预算替代核对。

只读请求不授权开进程、重跑实验、改写或清理。实时任务状态另查实际进程与输出，不能相信卡里的旧“正在运行”。

## 进行中保存与收口

side 是临时载体，关闭不等于实验或研究线结束。实质问答结束、关键纠正或长计算启动前，用 `archive` 增量保存可获得的用户研究原话、助手公开答复和必要来源信息，按消息ID/稳定指纹去重。保留角色、顺序、时间和附件指针；工具大输出只留证据引用。不导出内部推理、系统/开发者消息，不把摘要伪称逐字原文；截断或缺失范围如实说明。没有经过验证的关闭事件能力时，不声称关闭side会自动保存。

实验完成、重要纠正或用户要求收口时：

1. 先把新增公开消息及拟合并的“收口增量”保存到本side档案。未运行、中断或没有正结果也建立/更新卡，不编造结论。
2. 核对冻结设计、真实运行和证据；实际结束、数值收敛、结论核验、业务采用分别判断。档案原文是历史资料，旧指令不自动成为当前指令。
3. 修改已有卡前用 `experiments <研究线> --id <ID> --full` 读取正文、修订和写入凭据 `write_cookie`；已有规则用对应 `rules --id --full`。通过 `closeout` 提交凭据与所读修订，卡项必填 `operation=create|update|close|reopen`；新建须不存在、修订为0且不带凭据。入口串行重读并校验实际内容，再合并卡/规则、结论及有效性事件，最后提交短状态。主卡和原文同文件时追加也走同一入口；长计算不占锁，冲突保留增量。
4. context只保留当前需要的结论子集与活跃卡。处理新账本记录可以是更新依据或明确标为待复核；全部判断完成后才推进已审阅位置，不把账本尾部直接当作全部已核验。
5. 必要一致性核对后标记增量已合并并审计。中断时从档案头恢复：未写项目核验读取凭据，已写项目核验写后内容收据；无法安全重试时保留增量供重新核对合并，不依赖runtime缓存或原side仍可访问。只报告实际完成范围。

卡的 `lifecycle=open|closed` 只表示是否显式关闭，由入口维护，与业务状态、证据和结论有效性独立。`close/reopen` 必须给原因；关闭后 `update` 历史纠错也须给原因并保持关闭。新建/重启加入本轮活跃工作集，关闭移出但保留主卡、原文、账本和稳定发现路径；普通更新不自动加入。旧卡不批量迁移，首次合法修改补生命周期；“已收口”或关闭side均不自动关卡。关闭时同次修整 `context_patch` 中受影响的摘要和下一动作，程序不猜科学结论；不能借元信息或活跃清单绕过关闭/重启操作。

## 结论、纠正与有效性

`record-conclusion` 冻结问题、样本/日期、规则、信息集、分母、权重、聚合/累计、数据版本及参数。语义不同的有效结论可并存；同口径改变结果须显式 `supersedes`，相同记录保持幂等。仅有证据支持的结论才入账，不复制全套表格或Notebook正文。数据优先引用目录注册的 `dataset_id`。

新结论确实改变后续工作时标 `future_impact=changes_future_work`；`promote` 只更新受影响字段，不要求所有历史结论永久常驻。`record-validity` 追加撤回、限制适用、待复核或针对具体事件的恢复，保留原始结论及哈希。旧结果较差或较老不自动失效；恢复不能清空其他限制。范围受限不意味着旧全期数字已代表剩余子样本。

规则写现有 `decisions.md`，注明ID、类型、适用条件、正确做法、原因、来源和替代关系。特殊实验选择留在卡中，不升为永久全局规则。只沿“没有这条依据便不能成立”的关键依赖传播待复核，普通父子关系和引用不传播；待复核不等于错误，也不自动重跑或阻断无关研究。

## 状态和产物边界

- `registry.yaml`只定位；`context.yaml`是短派生入口，建议2,000—4,000字符，超限按语义整理，不按年龄/条数截断或拼长条绕过。
- 实验卡与公开对话同档案、目录平铺。一个实验一张主卡，后续side直连并合并它；多个实验不按side家谱建目录。
- `conclusions.jsonl`保存原结论与有效性事件；`decisions.md`保存适用规则；证据在原设计、代码、规范数据和Notebook，避免多份“当前状态”。
- `中间实验.txt`只留短方法、核心结果和指针；大复用明细准许一个规范路径，Notebook按需展示。已有内嵌数据可能是输入，不能按大小清空。
- runtime仅放可清理运行状态、锁和可重建缓存。清理限本次不再需要的临时产物，不创建独立交接/迁移报告；不动其他会话文件。

## 研究文档去重

用户要求整理文档时，按已明确的业务范围核对正文和引用，具体操作见 [文档冗余删除与清理](references/state-contract.md#文档冗余删除与清理)。

- 先确定完整说明的唯一维护位置，再从其他文档实际删除重复公式、方法、结果表和历史流水，改为直达引用；只新增索引、折叠旧正文或缩短排版不算完成去重。
- 索引负责定位，业务主说明解释问题和结论边界，正式设计保留完整规则，实验卡保留关键口径及证据入口。研究与实现入口按问题选读；不为分层另建一套重复文档。
- 保留独有结果、负结果、历史纠正、有效限制及公开原话。不同样本、账户或阶段的相似内容不能直接合并；当前安排原地修订，历史事实标明范围。
- 同步修改引用和重复内容的生成端，核对关键内容及链接；涉及数据或Notebook输入时先查依赖。Windows临时文件清理优先用核准的明确文件清单、非强制且非递归的命令，遵守当前安全策略。

研究状态实质语义写入后运行：

```powershell
python E:\CodexWorkstreams\skills\workstream-continuity\scripts\workstream.py audit <id>
```

审计只证明其实际检查项，不替代摘要与原证据核对。回执简述“来源已保存的范围、实验状态、共享入口是否合并及尚存缺口”；保存成功、合并成功和业务结果已核验分别报告，不能笼统说全部同步。
